Portfolio 4: NoSQL and Advanced Data Models

For Apex Digital Bank I looked at document and key value data models as an alternative to the relational database that we'd built for Portfolio 1.

The document model will group the customer details and account information into a JSON document. That makes it easier to pull together related information (particularly when you're working with an application that's going to need a flexible data structure).

The key/value model would represent the account numbers as the keys and the account balances as the values. That would allow for very fast lookups, though a production banking system would need a whole host of other controls in place to ensure the accuracy and consistency of the transactions.

For the practical demo I used SQLite's JSON functionality to store and retrieve a customer document. Created a JSON storage table and then successfully retrieved the customer details using json_extract().

Although SQLite is a relational database rather than a proper NoSQL system, this exercise has shown how document oriented data can be represented, validated and queried.
